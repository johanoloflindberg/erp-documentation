OAuth 2.0 enables your application to request delegated access to WEBBAB resources on behalf of a user, without ever handling that user's password. The user approves the access request directly on the WEBBAB platform, and your application receives a scoped access token it can use for subsequent API calls. This is the recommended flow when building third-party integrations that act on behalf of multiple WEBBAB users.

## OAuth 2.0 Concepts

Before diving into the implementation, make sure you are familiar with the key roles in an OAuth flow:

- **Resource Owner** — the WEBBAB user whose data your app wants to access.
- **Client** — your application, identified by a `client_id`.
- **Authorization Server** — the WEBBAB instance that issues tokens.
- **Resource Server** — the WEBBAB API endpoints your app calls using the token.

WEBBAB supports the **Authorization Code** flow, which is the most secure option for applications that can keep a client secret confidential (server-side apps, backend services).

## Register Your OAuth Client

<Steps>
  <Step title="Create an OAuth client">
    In your WEBBAB instance, navigate to **Integrations → OAuth Client** (or the equivalent path confirmed by your WEBBAB administrator) and create a new client application.
  </Step>
  <Step title="Configure the redirect URI">
    Set the **Redirect URI** to the callback URL in your application — for example, `https://yourapp.example.com/oauth/callback`. WEBBAB will redirect the user to this URL after authorization.
  </Step>
  <Step title="Note your credentials">
    Copy the `client_id` and `client_secret`. Store the secret securely; treat it with the same care as a password.
  </Step>
</Steps>

## Authorization Code Flow

### Step 1 — Redirect the User to WEBBAB

Construct an authorization URL and redirect the user's browser to it. WEBBAB presents a consent screen asking the user to approve the requested scopes.

```http
GET https://your-instance.webbab.se/api/method/frappe.integrations.oauth2.authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://yourapp.example.com/oauth/callback
  &scope=openid%20all
  &state=RANDOM_CSRF_TOKEN
```

<ParamField query="response_type" type="string" required>
  Must be `code` for the authorization code flow.
</ParamField>
<ParamField query="client_id" type="string" required>
  Your registered OAuth client ID.
</ParamField>
<ParamField query="redirect_uri" type="string" required>
  The callback URL registered for your client. Must match exactly.
</ParamField>
<ParamField query="scope" type="string" required>
  Space-separated list of scopes. Use `all` for full access or specify individual scopes (TODO — full scope list to be confirmed).
</ParamField>
<ParamField query="state" type="string">
  A random, unguessable value you generate. WEBBAB returns this in the callback so you can verify it to prevent CSRF attacks.
</ParamField>

### Step 2 — Handle the Callback

After the user approves access, WEBBAB redirects to your `redirect_uri` with an authorization code:

```text
https://yourapp.example.com/oauth/callback
  ?code=AUTHORIZATION_CODE
  &state=RANDOM_CSRF_TOKEN
```

Verify that the `state` value matches what you sent in Step 1 before proceeding.

### Step 3 — Exchange the Code for Tokens

Send a `POST` request from your server to the token endpoint to exchange the authorization code for an access token and refresh token.

<CodeGroup>

```bash cURL
curl --request POST \
  --url "https://your-instance.webbab.se/api/method/frappe.integrations.oauth2.get_token" \
  --header "Content-Type: application/x-www-form-urlencoded" \
  --data "grant_type=authorization_code" \
  --data "code=AUTHORIZATION_CODE" \
  --data "redirect_uri=https://yourapp.example.com/oauth/callback" \
  --data "client_id=YOUR_CLIENT_ID" \
  --data "client_secret=YOUR_CLIENT_SECRET"
```

```javascript JavaScript (fetch)
const params = new URLSearchParams({
  grant_type: "authorization_code",
  code: authorizationCode,
  redirect_uri: "https://yourapp.example.com/oauth/callback",
  client_id: process.env.WEBBAB_CLIENT_ID,
  client_secret: process.env.WEBBAB_CLIENT_SECRET,
});

const response = await fetch(
  "https://your-instance.webbab.se/api/method/frappe.integrations.oauth2.get_token",
  {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: params.toString(),
  }
);

const tokens = await response.json();
// { access_token, token_type, expires_in, refresh_token, scope }
```

```python Python (requests)
import os
import requests

response = requests.post(
    "https://your-instance.webbab.se/api/method/frappe.integrations.oauth2.get_token",
    data={
        "grant_type": "authorization_code",
        "code": authorization_code,
        "redirect_uri": "https://yourapp.example.com/oauth/callback",
        "client_id": os.environ["WEBBAB_CLIENT_ID"],
        "client_secret": os.environ["WEBBAB_CLIENT_SECRET"],
    },
)

response.raise_for_status()
tokens = response.json()
access_token = tokens["access_token"]
refresh_token = tokens.get("refresh_token")
```

</CodeGroup>

### Token Response

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "def50200abc...",
  "scope": "openid all"
}
```

<ResponseField name="access_token" type="string">
  The token to include in API requests.
</ResponseField>
<ResponseField name="token_type" type="string">
  Always `Bearer`.
</ResponseField>
<ResponseField name="expires_in" type="integer">
  Seconds until the access token expires.
</ResponseField>
<ResponseField name="refresh_token" type="string">
  Use this to obtain a new access token without user interaction. Store securely.
</ResponseField>

## Step 4 — Call the API with the Access Token

Include the access token in the `Authorization` header as a `Bearer` token:

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://your-instance.webbab.se/api/resource/Item" \
  --header "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  --header "Content-Type: application/json"
```

```javascript JavaScript
const response = await fetch(
  "https://your-instance.webbab.se/api/resource/Item",
  {
    headers: {
      Authorization: `Bearer ${accessToken}`,
      "Content-Type": "application/json",
    },
  }
);
```

```python Python
response = requests.get(
    "https://your-instance.webbab.se/api/resource/Item",
    headers={
        "Authorization": f"Bearer {access_token}",
        "Content-Type": "application/json",
    },
)
```

</CodeGroup>

## Scopes

The following scopes are expected based on standard Frappe Framework OAuth support:

| Scope | Description |
|-------|-------------|
| `openid` | Access the user's identity (ID token). |
| `all` | Full access to all resources the user can access. |

Request only the scopes your application genuinely needs to minimise the permissions you hold.

## Security Considerations

<Warning>
  Never expose your `client_secret` in client-side JavaScript, mobile app binaries, or any other context where end users could extract it. The authorization code flow with a confidential client is a server-side operation.
</Warning>

<CardGroup cols={2}>
  <Card title="Validate state parameter" icon="shield-check">
    Always verify the `state` value in the callback matches what you sent to prevent CSRF attacks.
  </Card>
  <Card title="Use PKCE for public clients" icon="lock">
    If you are building a single-page app or mobile app that cannot keep a secret, use PKCE (Proof Key for Code Exchange) instead of a client secret (TODO — verify PKCE support with WEBBAB team).
  </Card>
  <Card title="Store tokens securely" icon="database">
    Store access and refresh tokens in server-side session storage or an encrypted database. Never store them in `localStorage` in browser applications.
  </Card>
  <Card title="Revoke on logout" icon="right-from-bracket">
    Call the revoke endpoint when a user disconnects your app to invalidate their tokens immediately (TODO — verify revoke endpoint path).
