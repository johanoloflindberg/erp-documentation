## How to Read This Changelog

Each release entry follows this structure:

- **New** — Features and capabilities that did not exist before
- **Improved** — Changes to existing features that enhance behaviour without breaking existing integrations
- **Fixed** — Bug fixes
- **Deprecated** — Features that still work but are scheduled for removal; plan your migration now
- **Breaking Changes** — Changes that require action on your part; review before upgrading
- **Migration** — Step-by-step instructions for adapting to breaking changes

A change is marked **Breaking** if it:
- Removes an API endpoint, field, or parameter that was previously available
- Changes the format of a response field in a non-additive way
- Changes the semantics of an existing operation
- Removes a DocType or renames a field
