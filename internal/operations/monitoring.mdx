## Health Check Endpoints

Use these endpoints to verify that the application is up and reachable.

| Check | Endpoint | Expected response |
|---|---|---|
| Application ping | `GET /api/method/frappe.utils.ping` | `{"message": "pong"}` |
| Auth ping (session check) | `GET /api/method/frappe.auth.get_logged_user` | Returns current user or 403 |
| Static assets reachable | `GET /assets/frappe/css/desk.min.css` | HTTP 200 |

## What to Monitor

### Service-Level Checks

| Service | What to check | Alert condition |
|---|---|---|
| Gunicorn / App server | HTTP 200 on ping endpoint | No 200 for over 60 s |
| Nginx | Process running; no sustained 502s | 502 rate above **TODO** |
| MariaDB | Connection success; query response time | Connect failure; p99 latency above **TODO** |
| Redis (cache) | Ping response | No PONG for over 30 s |
| Redis (queue) | Ping response | No PONG for over 30 s |
| Scheduler | Heartbeat freshness | Last tick over 5 min ago |
| Workers | At least one worker per queue is alive | 0 workers on any queue |

## Frappe's Built-in Health Indicators

Frappe provides some built-in operational visibility:

### Scheduled Job Log

View recent scheduler execution in the desk:

**Desk → Scheduled Job Log** (`/app/scheduled-job-log`)

Each entry shows the job function, execution time, and status. Use this to confirm that scheduled tasks are firing.

### Background Job Monitor

**Desk → Background Jobs** (`/app/background-jobs`) shows:

- Currently running jobs
- Failed jobs (with traceback)
- Job queue depth per queue

### Error Log

**Desk → Error Log** (`/app/error-log`) — see [Logging](/internal/operations/logging).

### Frappe System Console (Admin only)

For immediate diagnostics, the System Console in the desk allows running Python snippets in the Frappe context. Use with care in production.
