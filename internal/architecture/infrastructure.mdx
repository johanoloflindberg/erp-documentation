|---|---|---|

## Network and Security Boundaries

The following describes the *shape* of the network boundaries. Actual firewall rules, CIDR ranges, and security group IDs are maintained by the ops team and are not documented here.

```
Internet
    │
    ▼  HTTPS (443)
  Nginx (edge)
    │
    ├─► Gunicorn (WSGI, internal port)
    ├─► Socket.IO (Node, internal port)
    │
    ▼  Internal network only
  MariaDB (internal port)
  Redis (internal port)
  File Storage (internal or S3 endpoint)
```

- All inter-service communication happens on an internal network not exposed to the public internet.
- MariaDB and Redis ports are **never** exposed publicly.
- TLS terminates at Nginx; internal traffic is plain HTTP (**TODO**: confirm if mTLS is used internally).

## Site Configuration

Frappe's per-site configuration lives in `sites/<site_name>/site_config.json`. This file contains database credentials, Redis URLs, and other site-specific settings. It is **never** committed to source control.

Key configuration keys used by WEBBAB:

| Key | Purpose |
|---|---|
| `db_name` | MariaDB database name |
| `db_password` | MariaDB password — use secrets manager |
| `redis_cache` | Redis URL for cache |
| `redis_queue` | Redis URL for RQ queues |
| `redis_socketio` | Redis URL for Socket.IO pub/sub |
| `host_name` | Public hostname of the site |
| `mail_*` | Outbound email configuration |
| `s3_*` | S3 storage credentials (if applicable) |

<Warning>
  The `site_config.json` file contains secrets. Treat it with the same care as a `.env` file. Access is controlled by file-system permissions on the server.
</Warning>
