Each app owns a distinct domain of functionality — from billing to integrations to the core platform — and exposes its capabilities to the rest of the system through Frappe's hook and permission mechanisms.

## App Documentation Format

When you document an app, follow the structure below. Copy the [App Template](/internal/apps/template) and fill in each section. A complete app entry includes:

<CardGroup cols={2}>
  <Card title="Overview" icon="circle-info">
    Purpose, business domain, and a one-paragraph description of what the app does.
  </Card>
  <Card title="Modules" icon="folder">
    List of Frappe modules inside the app and what each one covers.
  </Card>
  <Card title="DocTypes" icon="table">
    Table of all DocTypes: name, category (Document / Child / Single), and a one-line description.
  </Card>
  <Card title="API Endpoints" icon="plug">
    All `@frappe.whitelist()` methods exposed as RPC endpoints, with method path and purpose.
  </Card>
  <Card title="Hooks" icon="link">
    What the app registers in `hooks.py`: document events, scheduler events, permission hooks.
  </Card>
  <Card title="Background Jobs" icon="clock">
    Scheduled tasks and async jobs, including queue assignment and frequency.
  </Card>
  <Card title="Permissions" icon="lock">
    Roles defined by the app, default permission rows, custom permission logic.
  </Card>
  <Card title="Dependencies" icon="arrow-down">
    Other Frappe apps this app requires; external services it calls.
  </Card>
</CardGroup>

## Adding a New App

When a new Frappe app is created for WEBBAB:

<Steps>
  <Step title="Create the app">
    ```bash
    bench new-app webbab_<domain>
    ```
  </Step>
  <Step title="Install into the site">
    ```bash
    bench --site webbab.localhost install-app webbab_<domain>
    ```
  </Step>
  <Step title="Document the app">
    Copy [App Template](/internal/apps/template), fill in all sections, and open a PR to add the page to this inventory.
  </Step>
  <Step title="Update this page">
    Add a row to the inventory table above with the app name, domain, and link to the new docs page.
  </Step>
</Steps>
