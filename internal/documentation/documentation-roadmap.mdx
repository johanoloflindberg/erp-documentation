This page is the master tracking document for the WEBBAB documentation project. It records what has been written, what is missing, what technical inputs are needed before certain pages can be completed, and the recommended priority order for next steps. Owners and reviewers should update this page as work progresses.

<Info>
  This roadmap reflects the state of the documentation at the time of initial scaffolding. Every section marked **TODO** represents a gap that needs team input. The recommended priorities are a starting point — the team should adjust based on the most urgent support and developer needs.
</Info>

## 10. Recommended Priority Order

Based on the gaps identified above, the following priority order is recommended for the next documentation sprint:

### Immediate (P1 — blocks onboarding and daily operations)

1. **Fill Dev Setup TODO markers** — repository names, app install order, Frappe version. Without this, new developers cannot onboard.
2. **Fill Incident Response contacts** — on-call names, escalation paths. Without this, the runbook is not actionable.
3. **Apps Overview — app inventory** — add at minimum `webbab_core` with a docs page. This is the most fundamental reference.
4. **Infrastructure specifics** — single vs. multi-site decision; Redis topology; file storage backend. Needed for accurate ops runbooks.

### Short-term (P2 — needed for stable operations and developer efficiency)

5. **CI/CD pipeline documentation** — Testing and Deployment pages have large TODO blocks pending this.
6. **Observability tooling** — Logging and Monitoring pages need the tooling stack to be complete.
7. **OpenAPI spec import** — enables the Developer Portal API reference to be generated rather than hand-authored.
8. **Git strategy confirmation** — Standards page can then be used authoritatively in code reviews.

### Medium-term (P3 — improves coverage and completeness)

9. **Per-app documentation pages** — one page per Frappe app using the App Template.
10. **DocType reference pages** — for DocTypes used by external API consumers.
11. **Integration documentation** — one page per external integration.
12. **MCP server documentation** — once the MCP server is implemented.
13. **Security and permission documentation** — once decisions are made.

### Ongoing

- Keep the roadmap updated as items are completed or reprioritised.
- Run a documentation review every quarter — check for pages with outdated TODO markers.
- Add new pages to this roadmap when new platform features are implemented.
