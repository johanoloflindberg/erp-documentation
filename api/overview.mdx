The WEBBAB API gives you programmatic access to your platform data — customers, orders, invoices, projects, and more. It is built on top of the [Frappe Framework](https://frappeframework.com/) and exposes two complementary API styles: a **Resource API** for standard CRUD operations on DocType records, and an **RPC Method API** for calling specific server-side functions. Both styles accept and return JSON over HTTPS.

## Base URL

All API requests are made to your WEBBAB instance hostname. If you are on the WEBBAB cloud, your base URL follows this pattern:

```
https://your-instance.webbab.se
```

Replace `your-instance` with your actual subdomain. Self-hosted deployments use whatever domain your team has configured.

## Two API Styles

WEBBAB exposes two distinct URL namespaces, each serving a different purpose.

<CardGroup cols={2}>
  <Card title="Resource API" icon="database">
    Standard REST access to Frappe DocType records. Use this for listing, creating, reading, updating, and deleting business objects like customers, orders, or invoices.

    ```
    /api/resource/{DocType}
    /api/resource/{DocType}/{name}
    ```
  </Card>
  <Card title="Method (RPC) API" icon="code">
    Call whitelisted Python functions exposed by the Frappe application. Use this for actions that don't map cleanly to a single resource, such as bulk operations or custom business logic.

    ```
    POST /api/method/{dotted.python.path}
    ```
  </Card>
</CardGroup>

## Request Format

Every request must include the `Content-Type: application/json` header when sending a request body. Responses are always JSON. There is no XML or form-encoded support for resource endpoints.

```http
Content-Type: application/json
Accept: application/json
```

## Authentication

WEBBAB uses Frappe's token-based authentication. You pass an `Authorization` header containing your API key and secret on every request. No session cookies or OAuth flows are required for server-to-server integrations.

```http
Authorization: token YOUR_API_KEY:YOUR_SECRET
```

<Info>
  See the [Authentication guide](/api/authentication) for full details on generating credentials, header format, and handling auth errors.
</Info>

## Response Envelope

Successful Resource API responses wrap the payload in a `data` key:

```json
{
  "data": { ... }
}
```

List responses wrap an array:

```json
{
  "data": [ { ... }, { ... } ]
}
```

RPC Method responses wrap the return value in a `message` key:

```json
{
  "message": { ... }
}
```

Error responses use a different envelope — see the [Errors reference](/api/errors) for the full error object structure.

Frappe's built-in resource and method endpoints do not currently use a version prefix in the URL path (e.g. there is no `/api/v1/resource/…`). WEBBAB may introduce versioned namespaces for custom endpoints in the future. Until then, treat the base `/api/resource/` and `/api/method/` paths as the stable surface. See [API Versioning](/api/versioning) for the deprecation and migration policy.

## Quick Start

The fastest way to verify your credentials is to call the built-in `get_logged_user` method, which returns the username associated with your API token:

<CodeGroup>
```bash cURL
curl --request POST \
  --url https://your-instance.webbab.se/api/method/frappe.auth.get_logged_user \
  --header "Authorization: token YOUR_API_KEY:YOUR_SECRET"
```

```python Python
import requests

response = requests.post(
    "https://your-instance.webbab.se/api/method/frappe.auth.get_logged_user",
    headers={"Authorization": "token YOUR_API_KEY:YOUR_SECRET"},
)
print(response.json())  # {"message": "your-user@example.com"}
```

```javascript Node.js
const response = await fetch(
  "https://your-instance.webbab.se/api/method/frappe.auth.get_logged_user",
  {
    method: "POST",
    headers: { Authorization: "token YOUR_API_KEY:YOUR_SECRET" },
  }
);
const data = await response.json();
console.log(data); // { message: "your-user@example.com" }
```
</CodeGroup>

A `200 OK` response with your user's email confirms that your credentials are valid and your instance is reachable.
