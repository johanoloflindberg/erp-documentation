Creating and updating records in WEBBAB uses the standard REST resource API. A `POST` request to `/api/resource/{DocType}` creates a new document, and a `PUT` request to `/api/resource/{DocType}/{name}` updates an existing one. WEBBAB validates all submitted fields according to the DocType definition and returns structured errors when validation fails. This tutorial shows you how to handle both operations reliably.

## Create a Document

Send a `POST` request with a JSON body containing the document fields:

<CodeGroup>
```bash cURL
curl -X POST https://your-instance.webbab.se/api/resource/Customer \
  -H "Authorization: token YOUR_API_KEY:YOUR_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_name": "Acme Corp",
    "customer_type": "Company",
    "customer_group": "Commercial",
    "territory": "Sweden"
  }'
```

```javascript JavaScript
const response = await fetch(
  'https://your-instance.webbab.se/api/resource/Customer',
  {
    method: 'POST',
    headers: {
      'Authorization': 'token YOUR_API_KEY:YOUR_SECRET',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      customer_name: 'Acme Corp',
      customer_type: 'Company',
      customer_group: 'Commercial',
      territory: 'Sweden',
    }),
  }
);

if (!response.ok) {
  await handleApiError(response);
}

const { data } = await response.json();
console.log('Created customer:', data.name); // "CUST-00123"
```

```python Python
import requests

response = requests.post(
    'https://your-instance.webbab.se/api/resource/Customer',
    headers={
        'Authorization': 'token YOUR_API_KEY:YOUR_SECRET',
        'Content-Type': 'application/json',
    },
    json={
        'customer_name': 'Acme Corp',
        'customer_type': 'Company',
        'customer_group': 'Commercial',
        'territory': 'Sweden',
    },
)
response.raise_for_status()

data = response.json()['data']
print('Created customer:', data['name'])  # "CUST-00123"
```
</CodeGroup>

### Successful Response

A `200 OK` response contains the newly created document with all auto-populated fields (name, creation timestamp, owner, etc.):

```json
{
  "data": {
    "name": "CUST-00123",
    "customer_name": "Acme Corp",
    "customer_type": "Company",
    "customer_group": "Commercial",
    "territory": "Sweden",
    "creation": "2024-11-15T10:32:00.000Z",
    "modified": "2024-11-15T10:32:00.000Z",
    "docstatus": 0,
    "owner": "api-user@your-instance.webbab.se"
  }
}
```

Store the returned `name` field — it is the unique identifier you need for all future reads and updates on this record.

## Update a Document

Send a `PUT` request to update one or more fields on an existing document. You only need to include the fields you want to change — unchanged fields are left as-is:

<CodeGroup>
```bash cURL
curl -X PUT https://your-instance.webbab.se/api/resource/Customer/CUST-00123 \
  -H "Authorization: token YOUR_API_KEY:YOUR_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "territory": "Norway",
    "customer_group": "Enterprise"
  }'
```

```javascript JavaScript
const response = await fetch(
  'https://your-instance.webbab.se/api/resource/Customer/CUST-00123',
  {
    method: 'PUT',
    headers: {
      'Authorization': 'token YOUR_API_KEY:YOUR_SECRET',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      territory: 'Norway',
      customer_group: 'Enterprise',
    }),
  }
);

if (!response.ok) {
  await handleApiError(response);
}

const { data } = await response.json();
console.log('Updated customer:', data.name, '— modified:', data.modified);
```

```python Python
response = requests.put(
    'https://your-instance.webbab.se/api/resource/Customer/CUST-00123',
    headers={
        'Authorization': 'token YOUR_API_KEY:YOUR_SECRET',
        'Content-Type': 'application/json',
    },
    json={
        'territory': 'Norway',
        'customer_group': 'Enterprise',
    },
)
response.raise_for_status()
data = response.json()['data']
print('Updated customer:', data['name'])
```
</CodeGroup>

## Handle Validation Errors

WEBBAB returns `HTTP 417` (Expectation Failed) for field-level validation failures. The response body contains a structured error message:

```json
{
  "exc_type": "MandatoryError",
  "message": "Mandatory fields required in Customer:\ncustomer_name",
  "_server_messages": "[{\"message\": \"Mandatory fields required...\"}]"
}
```

Parse and surface validation errors clearly:

```javascript
async function handleApiError(response) {
  let body = {};
  try {
    body = await response.json();
  } catch { /* ignore parse errors */ }

  const message = body.message
    ?? body._error_message
    ?? body.exc_type
    ?? response.statusText;

  switch (response.status) {
    case 400:
    case 417:
      throw new ValidationError(`Validation failed: ${message}`);
    case 401:
      throw new AuthError('Invalid API credentials');
    case 403:
      throw new PermissionError('Insufficient permissions for this operation');
    case 404:
      throw new NotFoundError(`Resource not found: ${message}`);
    case 409:
      throw new ConflictError(`Conflict: ${message}`);
    default:
      throw new ApiError(response.status, message);
  }
}

class ValidationError extends Error { constructor(m) { super(m); this.name = 'ValidationError'; } }
class AuthError extends Error { constructor(m) { super(m); this.name = 'AuthError'; } }
class PermissionError extends Error { constructor(m) { super(m); this.name = 'PermissionError'; } }
class NotFoundError extends Error { constructor(m) { super(m); this.name = 'NotFoundError'; } }
class ConflictError extends Error { constructor(m) { super(m); this.name = 'ConflictError'; } }
class ApiError extends Error {
  constructor(status, m) { super(m); this.name = 'ApiError'; this.status = status; }
}
```

### Common Validation Errors

| Error type | HTTP status | Meaning |
|---|---|---|
| `MandatoryError` | 417 | A required field was missing or empty |
| `LinkValidationError` | 417 | A linked field references a document that does not exist |
| `DuplicateEntryError` | 409 | A record with this name/key already exists |
| `PermissionError` | 403 | Your API user lacks create/write permission on this DocType |
| `ValidationError` | 417 | Custom validation logic on the DocType rejected the value |

## Create a Document with Child Table Rows

Many Frappe DocTypes have child tables (e.g. Sales Order items). Pass them as an array in the appropriate field:

```javascript
const salesOrder = await fetch(
  'https://your-instance.webbab.se/api/resource/Sales Order',
  {
    method: 'POST',
    headers: {
      'Authorization': 'token YOUR_API_KEY:YOUR_SECRET',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      customer: 'CUST-00123',
      transaction_date: '2024-11-20',
      delivery_date: '2024-11-27',
      items: [
        {
          item_code: 'ITEM-001',
          qty: 10,
          rate: 1250.00,
        },
        {
          item_code: 'ITEM-002',
          qty: 5,
          rate: 800.00,
        },
      ],
    }),
  }
);
```

## Idempotent Upsert Pattern

If you are syncing from an external system and are unsure whether a record already exists, implement an upsert: try to fetch first, then create or update accordingly:

```javascript
async function upsertCustomer(apiClient, externalId, fields) {
  // Look up by a known external identifier stored in a custom field
  const existing = await apiClient.listDocuments('Customer', {
    filters: [['custom_external_id', '=', externalId]],
    fields: ['name'],
    limit: 1,
  });

  if (existing.length > 0) {
    // Record exists — update it
    return apiClient.updateDocument('Customer', existing[0].name, fields);
  } else {
    // Record does not exist — create it
    return apiClient.createDocument('Customer', {
      ...fields,
      custom_external_id: externalId,
    });
  }
}
```

<Tip>
For high-volume creates, the resource API processes one document at a time and will consume more API quota for large batches. Contact WEBBAB support to ask about bulk import options for your use case.
</Tip>
