WEBBAB is a modern SaaS business platform that gives companies a unified workspace for managing customers, orders, projects, support, and finances. Built on the open-source Frappe Framework, WEBBAB exposes every part of its data model and automation system through stable, documented APIs — so your integrations stay connected across the full lifecycle of your business.

## What WEBBAB Does

WEBBAB centralises the workflows that typically sprawl across disconnected tools. From a single platform your team can track leads and customers, manage sales orders and invoices, run projects, handle support tickets, and automate routine tasks. As a developer or integration partner, your role is to connect those workflows to the tools your customers already use — or to build new experiences on top of WEBBAB's structured data.

## Platform Capabilities

WEBBAB exposes the following integration surface to external developers.

### REST API

Every DocType in WEBBAB is automatically available as a REST resource at `/api/resource/{DocType}`. Standard CRUD operations — list, read, create, update, delete — work uniformly across all resource types. Responses are JSON.

### RPC Methods

Beyond CRUD, WEBBAB exposes named server-side methods over HTTP at `/api/method/{dotted.method.path}`. Use RPC calls for actions that don't map cleanly to resource operations: running a report, triggering a workflow step, or calling a business-logic function.

### Webhooks

Subscribe to document lifecycle events and receive HTTP POST notifications when records change. Webhooks carry a structured payload describing the changed document and the event type, allowing your systems to stay in sync without polling.

### MCP Server

The WEBBAB MCP (Model Context Protocol) server bridges the platform to AI agents. Clients that speak the MCP protocol can invoke WEBBAB tools, query resources, and execute actions through a structured conversation interface.

### Integration Layer

WEBBAB ships with a configurable integration framework for connecting external SaaS products. Each integration manages its own credentials, field mappings, and sync schedules — and can surface status back through the API.

## Multi-Tenant Model

WEBBAB is a multi-tenant platform. Each customer organisation runs in its own isolated tenant. When you authenticate with an API key, your credentials are scoped to a single tenant — you cannot read or write data belonging to another organisation.

<Info>
  Tenant isolation is enforced at the database and permission layers. See [Data Isolation](/security/data-isolation) for the complete model.
</Info>

## Key Components

| Component | Purpose | Protocol |
|---|---|---|
| REST API | CRUD operations on DocType resources | HTTPS / JSON |
| RPC API | Named method calls for business logic | HTTPS / JSON |
| Webhooks | Push notifications for document events | HTTPS POST |
| MCP Server | AI agent tool interface | MCP over HTTP |
| Integration Layer | Pre-built external service connectors | Per-integration |
