MCP resources are read-only data sources that the WEBBAB MCP server makes available to AI clients. Where tools are callable actions, resources are persistent data objects — similar to files or documents — that an AI client can read, reference in its context, and reason over. This page explains what resources are, how WEBBAB exposes them, and how to access them.

## What Are MCP Resources?

In the Model Context Protocol specification, a resource is any piece of data that can be read by an AI client and included in its context window. Resources are identified by a URI, have a defined MIME type, and are fetched via a `resources/read` request. Unlike tools, resources do not accept complex input arguments — they are accessed by URI.

Resources are well-suited for:

- Giving an AI assistant background context about a customer before a conversation
- Providing an agent with a reference document (for example, a product catalogue or pricing sheet)
- Supplying configuration data that the AI uses to make decisions

## Resource URI Format

WEBBAB MCP resources follow a consistent URI scheme:

```
webbab://{resource_type}/{resource_id}
```

Examples:

| Resource | URI |
|----------|-----|
| Customer C-1042 | `webbab://customers/C-1042` |
| Order O-5521 | `webbab://orders/O-5521` |
| Project P-007 | `webbab://projects/P-007` |
| Customer list | `webbab://customers` |
| Order list | `webbab://orders` |

## Reading a Resource

To read a resource, an MCP client sends a `resources/read` request with the resource URI:

```json
{
  "method": "resources/read",
  "params": {
    "uri": "webbab://customers/C-1042"
  }
}
```

The server returns the resource content:

```json
{
  "contents": [
    {
      "uri": "webbab://customers/C-1042",
      "mimeType": "application/json",
      "text": "{\"id\": \"C-1042\", \"name\": \"Anna Eriksson\", \"email\": \"anna@example.com\", \"created_at\": \"2024-03-15T09:22:00Z\"}"
    }
  ]
}
```

In practice, your AI client handles this protocol exchange automatically. In Claude, for example, you can say:

```
Read the WEBBAB customer record for C-1042 and summarise their contact information.
```

## Listing Available Resources

To discover what resources the server exposes, your client can call `resources/list`:

```json
{
  "method": "resources/list"
}
```

This returns all top-level resources and resource templates (URI patterns for dynamic resources) that the server makes available. The response includes the URI, name, description, and MIME type for each resource.

## Authentication and Access Control

All resource reads require authentication with a valid WEBBAB API key. Access to individual resources is governed by the same role-based access control that applies to read tools:

- A customer resource requires a role with customer read access.
- An order resource requires a role with order read access.
- Configuration resources may be accessible to all authenticated users, or may require specific roles.

See [Authentication](/mcp/authentication) for credential setup and [Security](/mcp/security) for the full authorization model.

## Resource Caching

AI clients may cache resource content to avoid redundant requests. Resources in WEBBAB reflect the current state of the platform — they are not versioned snapshots. If you need fresh data, ensure your client is not serving a stale cached copy.

<Tip>
  For frequently accessed reference data (such as configuration and status lists), caching is beneficial. For transactional data (orders, customer records), prefer fresh reads to avoid acting on stale information.
</Tip>
