MCP prompts are pre-built instruction templates stored on the WEBBAB MCP server. When an AI client invokes a prompt, the server returns a structured message sequence — a series of user and assistant turns — that guides the AI through a specific task using the correct context, tool calls, and output format. Prompts reduce the burden on users to write effective instructions from scratch.

## What Are MCP Prompts?

In the Model Context Protocol specification, a prompt is a server-defined template that the client can invoke by name, optionally passing arguments. The server returns a `messages` array that the AI client injects at the start of (or into) a conversation. This gives the AI the right context and instructions without the user needing to write them.

Prompts are particularly useful for:

- **Guided data entry** — Walk the AI through collecting all required fields before calling a write tool
- **Structured reporting** — Produce a consistently formatted summary of platform data
- **Workflow initiation** — Set up the right context for a multi-step task like onboarding a new customer

## How to Invoke a Prompt

Your AI client calls `prompts/list` to discover available prompts, and `prompts/get` to retrieve a specific prompt with its arguments filled in.

At the protocol level:

```json
{
  "method": "prompts/get",
  "params": {
    "name": "webbab_new_customer_onboarding",
    "arguments": {
      "customer_name": "Bergström Consulting AB"
    }
  }
}
```

The server returns a messages array that the client uses to initialise the conversation. In practice, your AI client exposes this through its own UI — for example, a slash command or a prompt picker.

In Claude Desktop, you may see WEBBAB prompts appear as slash commands or in the prompt library once the server is connected.

## Discovering Prompts at Runtime

Once your MCP client is connected to the WEBBAB server, ask your AI client to list available prompts:

```
What WEBBAB prompt templates are available?
```

This triggers a `prompts/list` call and returns the current set of prompts with their descriptions and required arguments.

## Using Prompts vs. Using Tools Directly

| Approach | When to use |
|----------|------------|
| **Prompts** | Guided, structured tasks where consistent output format matters; onboarding flows; multi-step processes |
| **Direct tool calls** | Ad hoc queries and actions; situations where you know exactly what you need |

Prompts and tools complement each other — prompts often orchestrate multiple tool calls internally.
