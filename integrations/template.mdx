## Error Handling

_Describe how the integration detects, logs, and responds to errors._

| Error type | Detection | Response | Retry? |
|------------|-----------|----------|--------|
| Network timeout | HTTP 5xx or timeout | Log and retry | Yes — see Retry Logic |
| Authentication failure | HTTP 401 | Alert ops team, halt sync | No |
| Validation error | HTTP 400 | Log details, skip record, continue | No |
| Duplicate record | HTTP 409 / duplicate key | Log, use existing record | No |
| Rate limit | HTTP 429 | Back off and retry | Yes |

## Troubleshooting

| Symptom | Likely cause | Resolution |
|---------|-------------|-----------|
| Records not syncing | Integration disabled or credentials expired | Check integration status in WEBBAB settings; re-enter credentials |
| Duplicate records in external system | Idempotency key not set | Enable idempotency key in integration config |
| Wrong field values in external system | Mapping misconfiguration | Review the field mapping table in integration settings |
| Webhook events not received | Incorrect webhook URL registered | Re-register the webhook URL in [External System] settings |
| Authentication errors | API key revoked | Regenerate key and update integration config |
