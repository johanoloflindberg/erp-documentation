Cloud storage integrations connect WEBBAB to external file storage systems. Instead of storing documents, attachments, and media assets locally on the WEBBAB server, these integrations route file storage to a dedicated cloud provider — giving you scalable, independently backed-up storage with flexible access controls and cost management.

## What Storage Integrations Do

**Document and file storage:**
- Attachments uploaded in WEBBAB (invoices, contracts, project files) are stored in the external storage provider rather than on the WEBBAB server
- File URLs served to WEBBAB users are generated by the storage provider (pre-signed URLs or CDN links)
- WEBBAB stores only the file metadata (name, size, type, storage path) internally

**Document archiving:**
- Completed project files and closed customer documents can be automatically archived to cold storage tiers
- Retention policies configured in the storage provider apply to archived files
- Legal hold and compliance workflows can be managed through the storage provider's native tools

**Media asset management:**
- Product images, marketing assets, and other media stored in the cloud are referenced in WEBBAB by URL
- Image transformation and CDN delivery can be handled by the storage provider

## Typical Architecture

```
User Uploads File in WEBBAB
        │
        ▼
WEBBAB Integration Layer
  - Generate storage path (bucket / container / folder)
  - Upload file to cloud storage provider
  - Store file metadata + storage path in WEBBAB
        │
        ▼
Cloud Storage Provider
  - File stored in configured bucket/container
  - Access policy applied
        │
        ▼
User Accesses File
  - WEBBAB generates a pre-signed URL or CDN link
  - File served directly from cloud storage to user
```

## Authentication Patterns

| Provider | Method | Notes |
|----------|--------|-------|
| Amazon S3 | IAM Role or Access Key + Secret | Prefer IAM roles with instance profiles over long-lived access keys |
| Azure Blob Storage | Service Principal or Managed Identity | Managed Identity preferred for Azure-hosted deployments |
| Google Cloud Storage | Service Account key JSON | Store JSON key securely; rotate regularly |
| S3-compatible (MinIO, Wasabi, etc.) | Access Key + Secret | Same pattern as AWS S3 |

<Warning>
  Limit the IAM or service account permissions to the minimum required — typically read and write to a specific bucket. Do not use root credentials or overly broad permissions for storage integration service accounts.
</Warning>

## Configuration Considerations

When configuring a storage integration, decide on:

**Bucket / Container structure:**
- Single bucket for all WEBBAB files, with folder-based organisation by tenant, resource type, and date
- Or separate buckets per data classification (for example, a separate bucket for financial documents with stricter access controls)

**Access control:**
- Pre-signed URLs with short expiry times (15–60 minutes) for file downloads — this prevents unauthorised access if a URL is shared
- Public-read ACL only where genuinely required (for example, public product images)

**Encryption:**
- Enable server-side encryption at rest using provider-managed keys (SSE) as a baseline
- Use customer-managed keys (CMK/BYOK) if your compliance requirements demand it

**Versioning:**
- Enable object versioning for documents that may be overwritten (contracts, signed documents) to maintain an audit trail

## Data Residency

If your organisation has data residency requirements (for example, GDPR Article 44 transfer restrictions), ensure your storage bucket or container is in the correct region before configuring the integration.

## Error Handling

| Error | Action |
|-------|--------|
| Upload failed (network error) | Retry with exponential back-off; alert if persistent |
| Bucket/container not found | Verify configuration; check if bucket was accidentally deleted |
| Access denied | Check service account permissions; ensure bucket policy allows WEBBAB's service account |
| Pre-signed URL expired | Generate a fresh URL on request; do not cache URLs beyond their expiry |
| File not found | Log missing file; flag WEBBAB record for review; file may have been deleted outside WEBBAB |
